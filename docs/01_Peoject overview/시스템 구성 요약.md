# 전체 시스템 구성

## 1. 시스템 아키텍처

CUBIC은 **고수준 연산 계층, 실시간 제어 계층, 센서 계층, 구동·전원 계층**으로 구성된다.

| 계층       | 주요 구성                               | 담당 기능                                         |
| -------- | ----------------------------------- | --------------------------------------------- |
| 고수준 연산   | Raspberry Pi 5 8GB, ROS 2 Jazzy     | SLAM, Localization, Navigation, 센서 융합, 시스템 관리 |
| 실시간 제어   | Raspberry Pi Pico 2 ×2              | 모터 제어(MCU), 전원 관리(PCU)                        |
| 환경·상태 인식 | RPLIDAR C1 ×2, BNO055               | 주변 거리, 자세 및 각속도 측정                            |
| 구동       | XD42XA-4260WSY-24V300R ×2              | Differential Drive 방식 이동                      |
| 전원       | 7S Li-ion 24V 20Ah, INA226, WCS1800 | 전력 공급 및 배터리 상태 계측                             |
| 개발·모니터링  | Foxglove, Ethernet, Wi-Fi AP        | 상태 확인, 원격 제어 및 디버깅                            |

---

## 2. 연산 및 제어 구조

### Main Computer — Raspberry Pi 5

로봇 전체의 고수준 연산을 담당한다.

* ROS 2 Jazzy 실행
* LiDAR 데이터 통합 및 환경 인식
* IMU / Odometry 데이터 융합
* SLAM Toolbox 기반 지도 생성
* AMCL 기반 위치 추정
* Nav2 기반 경로 계획 및 자율주행
* URDF / Xacro 및 TF 관리
* Foxglove 기반 모니터링

### Motor Control Unit — RP2350

구동계의 실시간 제어를 담당한다.

* ROS 2 `/cmd_vel` 명령 처리
* 좌·우 모터 목표 속도 계산
* PWM / DIR 출력
* FG 피드백 측정
* 실제 회전 속도 계산 및 제어
* Wheel Odometry 생성
* 통신 Watchdog 기반 안전 정지

### Power Control Unit — RP2350

구동 제어와 별도로 로봇의 전원 상태를 관리한다.

* 배터리 전압·전류 측정
* 잔량(SOC) 계산
* 전원 이상 감시
* Battery / Fault 상태 전송
* 시스템 상태 Buzzer 출력

## 3. 자율주행 정보 처리 흐름

```text
[ RPLIDAR Front ] ─┐
                    ├─→ Scan Fusion ───────────────┐
[ RPLIDAR Rear  ] ─┘                               │
                                                   │
[ Wheel FG ] → MCU → Odometry ─┐                   │
                                ├─→ EKF            │
[ BNO055 ] ─────────────────────┘      │           │
                                       │           │
                                       ▼           ▼
                                  odom / TF      /scan
                                       │           │
                         ┌─────────────┴───────────┐
                         │       Mode Manager      │
                         └─────────────┬───────────┘
                                       │
                    ┌──────────────────┴─────────────────┐
                    │                                    │
                    ▼                                    ▼
             [ Mapping Mode ]                    [ Navigation Mode ]
                    │                                    │
             SLAM Toolbox                     Map Server + AMCL
                    │                                    │
              Map Generation                             ▼
                                                        Nav2
                                                         │
                                                     /cmd_vel
                                                         │
                                                         ▼
                                                        MCU
                                                         │
                                                         ▼
                                                 Left / Right Motor
```


전·후방 LiDAR는 주변 환경 인식에 사용하며, Wheel Odometry와 IMU는 EKF를 통해 결합한다. 생성된 위치·환경 정보를 기반으로 Nav2가 이동 명령을 생성하고, Motor Control Unit이 실제 구동계를 제어한다.

전원 계통은 이 제어 흐름과 독립적으로 PCU에서 지속적으로 감시한다.

## 5. 시스템 설계 원칙

CUBIC의 시스템은 다음 세 가지 방향을 중심으로 설계하였다.

**연산 분리**
Linux 기반 SBC가 복잡한 자율주행 연산을 수행하고, 시간 민감도가 높은 모터·전원 처리는 별도의 RP2350이 담당한다.

**표준 인터페이스 활용**
ROS 2, micro-ROS, UART, USB, Ethernet 등 범용 인터페이스를 사용하여 센서와 제어 장치의 추가 및 변경이 가능하도록 구성하였다.

**독립적인 안전 계층**
비상정지 회로, 통신 Watchdog, 배터리 상태 감시 등을 통해 상위 소프트웨어와 별개로 기본적인 구동·전원 안전 기능이 동작하도록 구성하였다.

---

> 개별 부품 사양, 회로 및 배선은 Hardware 문서에서, MCU/PCU 제어 로직은 Firmware 문서에서, ROS 2·SLAM·Navigation 구성은 Software 및 Navigation 문서에서 각각 상세히 다룬다.
